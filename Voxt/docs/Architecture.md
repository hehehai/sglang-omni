# Source layout and runtime boundaries

Voxt is a macOS 26.2+ menu bar application, built with the shared `Voxt` Xcode scheme. Build instructions live in [CONTRIBUTING](../CONTRIBUTING.md); dependency pins and model validation requirements live in [MLXAudioDependency](MLXAudioDependency.md).

## Source map

| Directory | Responsibility |
| --- | --- |
| `Voxt/App/` | Application lifecycle, dependency assembly, feature routing, text delivery and window coordination |
| `Voxt/App/Recording/` | Recording start/stop, capture and output routing |
| `Voxt/Core/` | Shared values, persistence, preferences, prompts, security, logging and runtime support |
| `Voxt/Core/LLM/` | Execution plans, provider payloads, remote requests, parsing and answer models |
| `Voxt/Core/History/`, `Voxt/Core/Dictionary/` | Domain stores, repositories and query/value support |
| `Voxt/Core/Notes/` | Note storage, external export state and Obsidian/Reminders sync |
| `Voxt/Core/Models/` | Local LLM/GGUF loading, installation, downloads and model storage support |
| `Voxt/Core/Transcription/` | Capture metrics, VAD planning, ASR hints and transcript support |
| `Voxt/Transcription/` | Speech and MLX transcription, ASR model management |
| `Voxt/Transcription/RemoteASR/` | Remote ASR capture, upload and streaming protocols |
| `Voxt/Meeting/` | Meeting coordination and live sessions; capture, processing and speaker-analysis subdomains |
| `Voxt/Hotkey/` | Event handling, trigger rules, preferences and shortcut recording |
| `Voxt/Settings/` | SwiftUI settings and onboarding; `Shell/` owns navigation and shared presentation |
| `Voxt/Windows/` | AppKit windows, overlays, detail views and their view models |
| `Voxt/Resources/`, `*.lproj`, assets | Bundled prompts, runtimes, localization and visual resources |
| `VoxtTests/` | App tests; `TestSupport/` contains shared fixtures, doubles and model-test gates |
| `Packages/OmniXPCContracts/` | Dependency-free Foundation contracts, bounded wire codecs and standalone package tests shared by the app and helper |
| `Packages/OmniModelArtifacts/` | Bounded artifact validation, cooperating directory leases and atomic publication; Foundation/system POSIX only, no model loading or XPC dependency |
| `OmniInference/` | Opt-in XPC service, connection/model lifecycle, final/realtime sessions and Native C ABI leases |
| `tools/`, `Config/`, `packaging/` | Validation/build scripts, signing configuration and packaging inputs |

`Voxt/Voxt/Info.plist` is referenced by the build settings; the nested directory is not an orphan. There is no `Voxt/UI/` directory. The app and app-test targets use file-system-synchronized Xcode groups; the XPC helper has explicit source membership and shares a local package product with the app. Preserve membership exceptions, helper registrations and resource references when moving files.

## Main paths

- `AppDelegate` assembles model managers, stores, transcribers and UI coordinators. Its extensions route hotkeys, recording, translation, rewrite, notes and meetings. `LLMRequestLifecycle` owns request validity and outstanding work; `TrackedTaskStore` retains cancelled capture/LLM/audio submission tasks until exit rather than treating cancellation as completion.
- Recording selects a `TranscriberProtocol` implementation. MLX planning, merging, preview text, capture buffers, detached inference and structured segment conversion are in separate files under `Transcription/`. `MLXTranscriber` still owns task cancellation, session revision and model leases; the split does not change that lifetime boundary.
- LLM tasks compile into requests before local or remote execution. `RemoteLLMRuntimeClient` routes compiled requests; sibling extensions own Responses execution, chat completion execution, request construction, provider settings and runtime policy. Existing endpoint/message/parser helpers remain shared with connectivity checks.
- `RecordingSessionLifecycle` controls identity, cancellation and exactly-once output/end admission; capture/UI/timing remain separate. Final output is prepared once as an immutable `SessionFinalizeContext`, then delivered to the input target or answer UI. The delivery callback checks that same session before recording history and dictionary evidence. `TextInputIO` retains input inspection, `TextOutputDelivery` owns integration with paste/key posting, and `TextInjectionTransaction` validates queued work and completes once. Separate output generations permit follow-up keys after normal teardown but reject begin/cancel/dismiss; temporary clipboard restoration checks write ownership. There is no editor acknowledgement or cross-process clipboard CAS. Session-end orchestration remains under `App/Recording/`; there is no generic finalize-stage runner or active preview-replacement pipeline.
- Remote ASR retains recording/generation ownership in `RemoteASRTranscriber`, with file requests and provider streams in sibling files. Provider response actors freeze terminal text and respect cancellation. Dictation and meetings share bounded Doubao framing/gzip and Aliyun endpoint helpers, not their different transcript projection policies.
- Meeting coordination combines microphone/system audio, live transcription and final processing. Remote provider classes are separate; their base session owns ordered buffering, stop deadlines and exactly-once cleanup. `MeetingLiveSessionRegistry` pairs sessions with tokens (including draining sessions); the coordinator has a cleanup barrier before reuse of archive, VAD and model resources. File imports have a separate task owner and per-import transcriber/audio/model-use pipeline. Live finalization snapshots metadata and keeps its stop barrier until checkpoint cleanup; real device/model integration still requires acceptance.
- History and dictionary persistence use repositories backed by `VoxtDatabase` (GRDB/SQLite), with legacy-data migration. Their domain/Codable values are in `TranscriptionHistoryModels` / `DictionaryModels`; stores still own mutable snapshots, caches and writes. Notes and external sync have separate stores/coordinators. Suggestion models/scan policy are separate from mutable scan state and legacy suggestion-file compatibility. New history scans add directly to the dictionary; the retired empty discovery chain no longer runs, while old history suggestion snapshots still decode.

Resumable transfer is shared under `Core/Models` in separate types/delegate/transport files. Custom LLM request policy/tokenizer adaptation and GGUF runtime have their own files; managers retain mutable state. Remote-provider option/default resolution is separated without moving protected credential presence or runtime construction outside their `fileprivate` boundary.

Shared model loading uses `Core/Models/SharedModelLoadCoordinator<Value>`: current waiter entries and outstanding native-loading tasks have different lifetimes. Cancelled generations remain waitable by shutdown and block idle reclamation until they actually return. Manager shutdown callers share one complete cleanup task.

## Permission and input boundaries

LLM requests are text-only. Automatic foreground-window text/structure capture, screenshots, image attachment models and debug capture have been removed. App identity snapshots still support App Branch, dictionary scope and delivery targeting; selected-text operations are retained. Some text-generation checkpoints still require MLXVLM's loading factory.

Global hotkeys and shortcut recording use Accessibility-backed modifying event taps (with local recording fallback), not Input Monitoring/HID listeners. Recording mute changes the current output device's writable mute property and restores only owned changes; it also mutes Voxt sounds. It does not create an audio tap. Meeting system audio still uses a public Core Audio process tap and requests access when capture starts, without private TCC preflight. Screen Recording is no longer requested. See the [implementation and pending macOS validation](ContextEnhancementRemovalImplementation.zh-CN.md).

## Current limitations and maintenance rules

Most feature code remains in one app target. `AppDelegate` still owns substantial cross-feature state, and some shared preference types reside under `Settings`; directory names alone do not enforce a dependency boundary. OmniXPCContracts is an actual independent local Swift package, imported directly by both the app and helper without re-export aliases or duplicated target compilation. It owns Foundation configuration, validation, references and wire schemas, not model loading, backend selection or UI.

The opt-in XPC helper retains one connection-owned model and admits one final or realtime session at a time. Model lifecycle, final commands, realtime commands, event ACK retention and C ABI leases are cohesive service units. Native commands/drain run on the helper's serial queue; cancellation bypasses it, and unload/replacement stays blocked until worker cleanup completes. One encoded event batch is retained until its complete ACK, so lost-reply retries do not silently consume output.

OmniXPCStreamingSession implements the existing ASRStreamingSession seam with bounded audio and latest-state presentation. Successful/failed results follow Native drain/cleanup; cancellation can finish presentation without a result, but only waitUntilClosed or closeAndWait is the resource barrier. Structured consumeEvents drains on early exit, error or cancellation; raw AsyncStream consumers must explicitly closeAndWait after breaking early. This validation path remains capped at 30 seconds and is not yet production routing or a long-meeting backend. The production Native HTTP path and LLM/VLM paths remain unchanged.

Auxiliary model download verification is separate from inference. Silero and Sortformer provisioning use OmniModelArtifacts to check config and safetensors headers without instantiating MLX models or reading tensor payloads; malformed newly downloaded artifacts fail before cache publication. The real Silero inference loader remains in SileroVADModelLoader with its scoped MLX error conversion, and existing cached-directory presence scans retain their semantics. Structural checks do not prove model-key/config compatibility, GPU correctness, checksums or atomic/lease-safe replacement. Native Core ABI4 now exposes bounded Silero offline requests and continual streaming leases. One persistent dedicated worker owns its model and native stream states, serializes input copying/inference, and releases MLX resources on that same thread. Independent cancellation is not drain; terminal drain waits for work before clearing native state. Live stream leases retain the model after its public handle is destroyed. Legacy Qwen ABI layouts/functions and HTTP algorithms remain unchanged.

The opt-in helper now also exposes offline Silero load/request/cancel/unload RPCs and a typed App client. Silero and Qwen have independent connection lifetime state, locks, queues and token owners; shared service admission only serializes model-load registration and the idle diagnostic check. Silero deadlines cancel that request/load operation without invalidating healthy Qwen ownership. A cancellation ACK is not drain: unload/replacement remain blocked until the Native request returns. Owned sample ranges are identity/shape/budget-checked; no audio replay or fallback is introduced.

Signed smoke accepts an optional Silero directory, checks repeatable same-model sample ranges and reuse after helper reconnect alongside the loaded Qwen model. This is not range-accuracy or concurrent-GPU certification. Opt-in Silero streaming RPC now supports up to sixteen independent leased states, two-second chunks, one byte-identical last-reply cache per stream, and terminal finish/close barriers. The concrete voice-activity actor returns the latest real whole-frame probability or nil; explicit finish pads its tail. Structured withSileroVoiceActivityStream awaits close on return/error/cancel. Raw actors/references require explicit close; cancellation ACKs and presentation errors are not resource barriers. Failed barriers retain ownership and permit later close retry; proven rejected starts release only provisional client slots. The helper separates lifecycle, offline requests, stream state, stream commands and Native leases.

Sortformer Core ABI5 now provides bounded, independent streaming model leases and owned frame/speaker probabilities and segments on its dedicated worker. Native configuration is type/range-checked before narrowing or allocating models; safe legacy HTTP coercion remains unchanged. After merging upstream 7f78bf3, the current eleven ASR catalog checkpoints map to Native HTTP servers; Qwen/MOSS/Nemotron support realtime, while Whisper/Cohere/Parakeet/SenseVoice remain batch-preview. All six previously HTTP-only families now also have opt-in bounded final Core/XPC routes (at most 30 seconds), using the actual transcribers on persistent workers. This does not add their realtime/longform Core/XPC consumers or remove remaining Audio-dependent configuration/auxiliary execution. Sortformer now has eight opt-in RPCs, including an original-load-ID drain barrier, dedicated helper model/stream ownership, explicit settings and bounded four-speaker probability/absolute-time segment batches, plus an App client/actor and structured scope. Exact last-push server replay never reinfers audio; successful finish/close await Native drain/destroy, while failed barriers retain ownership for retry. The meeting consumer now has an explicit XPC adapter with externally owned preloaded models, bounded feeds and awaited stream cleanup; the common/default dispatcher and Native HTTP engine use an Audio-free Foundation configuration projection, while Swift fallback is isolated in its legacy adapter. Default production routing and remaining cache migration/recovery are not switched or completed. Native HTTP runtimes now hold cooperating canonical directory readers from before spawn through actual child exit for all seven ASR families, Silero and Sortformer; shutdown deadlines never substitute for exit. Sortformer configuration reads hand off a reader to that runtime. Legacy Sortformer meeting/realtime consumers now pin paired model/directory readers across construction, cached ownership and active feeds; reset/file cleanup cannot release an in-flight reader. Shared-directory migration, other legacy Swift readers, repair/shadow/blob coordination and parent-crash/orphan cleanup remain incomplete. Current Core/helper/App require ABI9 and 69 exports (ABI6 introduced checked Sortformer release): checked Sortformer stream/model destruction surfaces failure and retains handles/readers, including cancelled unpublished loads and failed unload retry. Load errors await scoped drain; failure/deadline retains a retryable ticket, while disconnect remains unconfirmed. Closed load IDs are non-evicting within a 256-entry connection budget; late loads cannot admit after drain, and cleanup tasks coalesce only for their originating load. Successful loads retain their original operation in one current model binding: explicit model-scope close drains live/provisional streams, resolves lost unload replies, blocks new/late work and retains failed retirement for retry. Cleared success-model maps after disconnect are not Native release proof; an explicit Sortformer model owner now authorizes the supplied shared Models path, reads scheduling configuration under an App reader, and retains that reader through model retirement. Model preparation and cleanup use identity-bound owned coordinator permits; unconfirmed failure/connection loss keeps the lane for original-scope retry. Priority-110 cleanup bypasses pressure/recording deferral but not an active lane. The actual XPC meeting adapter now retains identity-owned permits for open/feed/close, including failed provisional opens. Explicit engine close cancels and awaits its active command before checked cleanup; ambiguity retains its ticket and lane. Model Owner caches that concrete engine, permanently retires it before acquiring model-cleanup admission, and rejects late borrowed work. The signed smoke uses this owned consumer path; default production factories remain unchanged. Legacy C functions/layouts remain, but matching artifacts must be rebuilt. Qwen/Silero legacy void destruction is not covered by this checked-release change. Signed NSXPC/Metal/model acceptance remains pending.

Model publication now uses nonblocking cooperating shared-reader/exclusive-mutation directory leases and same-filesystem atomic exchange, never deleting the installed destination before commit. Reader leases span opt-in Qwen/Silero Native and stream ownership. A committed publication stays successful if old-payload cleanup fails; retained staging is quarantined rather than resumed blindly. Publication requires canonical sibling staging/destination and stable future symlink targets. Nested coordinated model roots explicitly reject, preserving persistent lock namespaces. This is not hostile-UID protection, immutable file snapshots, fsync/power-loss durability or automatic crash recovery; original user paths/selections and legacy reader/repair/shadow behavior outside this checkpoint are not automatically migrated. CPU/platform/model-stand-in tests, Swift header/link checks and pure timestamp replay do not certify NSXPC signing, Metal, real-model inference or concurrent ASR/VAD GPU safety.

Run swift test --package-path Voxt/Packages/OmniXPCContracts or swift test --package-path Voxt/Packages/OmniModelArtifacts without building the app or installing models. Portable package/app-lifecycle tests and CPU Native integration do not certify macOS NSXPC, signing, Metal or model inference; see the current [migration gates and evidence](../plan/OmniXPCIntegrationPlan.zh-CN.md).

Explicit shared-model preparation uses OmniModelPreparation through bounded ModelDiskOperations. A source reader spans dereferenced regular-file copying and staged validation; a sibling staging lease spans atomic publication. Existing destinations require explicit replacement authorization, readers exclude replacement, and original installed weights are unchanged. Failed hidden staging is retained for deliberate recovery. Entry/file-byte budgets do not bound the initial directory listing or certify external blob immutability. Signed smoke now stages through this App path instead of Python copytree, and its probe guard matches ABI9; actual signed execution remains pending.

Legacy Swift Silero actors now pin paired model/readers and reject cancelled/reset acquisitions without resurrecting caches. ASRAudioSampleRateConverter extracts the pinned AVAudioConverter algorithm without substituting the meeting linear resampler; Native input preparation no longer imports AudioCore. Remaining Audio STT/VAD/config/adapters still require the package; real SDK/audio DSP comparison remains pending.

MOSS and Nemotron HTTP realtime now delegate to their transport-free typed engines, reusing the existing numerical transcribers/stream implementation. Shared speaker events preserve absent preview segments versus present final/completed segments, speaker times and metadata. Original window/cadence/token budgets, nearest chunk presets, optional settings and stream tail behavior remain unchanged; actual CPU Before/After replays check observable inputs/options/events, not Metal/model quality. Engine Close cancels, wakes waiting commands and joins event delivery, **not** queued/GPU/model work. A model/worker must outlive the engine and actual worker drain. HTTP Close is virtual and callback-close retirement is deferred until transport delivery unlocks, avoiding transport/engine lock inversion. Core ABI8 now adds thirteen bounded Native speaker model/stream exports (69 total), and strict Foundation speaker DTOs. The new independent models use one lease until checked stream destruction; Native drain queues an actual loading-thread barrier, synchronizes, resets engines/caches on that thread, clears cache and synchronizes again. Failed cleanup retains the original handle/lease, including nonnull failed-create outputs when retirement is unconfirmed. Nemotron can prepare its stream on that worker without altering HTTP lazy/default behavior. Only these Native workers disable automatic idle cache release; explicit checked jobs contain sync/cache failures, while existing workers keep their default policy. Native ingress is finite mono16k, ≤32000 samples/chunk and ≤480000/session, with bounded owned events and no replay/truncation. Matched App/helper/Core now require epoch9 for ten actual speaker RPC selectors. The independent helper retains authorized readers and nonnull failed-create handles until checked retirement, with bounded original-load/session histories and complete-batch poll replay. Raw clients retain exact original bindings and load tickets across unknown cleanup/disconnect. OmniXPCSpeakerModelOwner explicitly prepares and starts sessions, retaining one owned coordinator permit throughout asynchronous decoding; ACK, terminal events and empty polls are not barriers. Checked session close releases the lane while preserving model residency; permanent original-load close releases model readers. Actual opt-in Owner/client/helper/Core CPU chains are exercised with explicit platform/model/MLX hooks. An opt-in OmniXPCSpeakerStreamingSession now consumes the actual ASRStreamingSession seam using the existing bounded input/presentation buffer. It permanently retires its entrusted Owner before ended publication and preserves complete segment metadata/Double times, with existing MOSS line/Nemotron script-aware joining. Unknown cleanup self-retains; checked permanent Owner-close notification releases it even after external original-scope retry. Optional signed smoke stages explicit speaker fixtures and uses this consumer before/after reconnect, retaining ambiguous owners without invalidating their client. Production recording/meeting factory cutover, longform and actual SDK/signed NSXPC/Metal/model acceptance remain pending.

The six-family batch helper retains directory/model/request ownership through checked destruction, including failed loads, model BUSY and request-destroy failure. Cancellation bypasses the command queue but is not drain. Client tickets survive disconnect and close only their original load scope; bounded histories retain late-work tombstones. The explicit BatchModelOwner now reserves identity-owned file/final ASR permits for model preparation and requests, reads structural artifacts under an App reader, and retires only the original load scope on failure. Successful commands free the lane but keep the resident model/reader; unknown cleanup retains ownership for explicit close retry. Permanent coalesced close cancels and awaits active work before model retirement, never reserving behind its own retained permit. This remains explicit final-only opt-in: default production ASR caller cutover, MOSS/Nemotron typed realtime, longform and dependency removal are not complete.

Keep framework/UI work at presentation and integration boundaries; prefer pure value/planning logic for testable decisions. Reuse existing managers and stores before adding abstractions. Split by ownership or protocol responsibility, not arbitrary line counts. Do not broaden every `private` member merely to enable file splitting.

The project enables default MainActor isolation and approachable concurrency. Preserve explicit `nonisolated`, `Sendable`, task cancellation and ownership assumptions when extracting code. Existing `@unchecked Sendable` types require case-by-case review, not mechanical annotation removal.

Hotkey tap installations own their source, callback context and dedicated thread independently of routing state. Queued work is generation-scoped; business actions run outside the routing lock. Native MLX streams similarly own their event/feed tasks and transferred model use in `MLXNativeLiveRuntime`, but the library's synchronous cancellation is not an awaitable native-worker barrier.

MeetingDetail separates window/controller setup, window layout, playback controller/pane and read-only presentation policy. Its view model keeps async work and mutable published state; the parent view still owns the player and transcript/scroll synchronization.

Settings sidebar/header/footer and notification/feedback dialogs have dedicated files. History note rows retain their local editing state and private footer controls separately from list/filter presentation. Browser permission probes and connectivity protocol helpers are split without changing their existing authorization, payload or timeout policies. Remote provider sheet validation and configuration snapshots have separate extensions; the parent still owns form state, while `RemoteProviderSheetOperations` owns scoped requests, result identity and retirement. Connectivity probes pair socket/session cleanup and close transport before waiting on timed-out receives. Onboarding step implementations and presentation components are separated, but SwiftUI state remains owned by `OnboardingGuideView`; cross-file extensions are not independent state owners.

The concentrated closeout also tracks retiring MLX/remote-preview tasks, serializes meeting VAD preparation with cleanup, and prevents stale dictionary reads from replacing newer snapshots. Five stateful coordination files remain above the review threshold by explicit ownership decision, not by exposing their private state to file slices. See the [closeout and real-environment acceptance checklist (中文)](RefactoringCloseout.zh-CN.md).

Installation presence is asynchronous: callers must not turn an unknown cache result into a missing-model warning. Settings shell/catalog listen to a shared debounced installation-revision publisher instead of polling or observing every progress change. Structured log metadata is redacted by sensitive key as well as value, including nested dictionaries and arrays.

The subsequent [performance/security audit (中文)](PerformanceSecurityReview.zh-CN.md) records new findings and still-open boundaries. Earlier closeout is not a claim that future audits will find no issues.
